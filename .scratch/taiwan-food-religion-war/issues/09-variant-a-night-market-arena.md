# 09 — 套用 Variant A 招牌擂台

**What to build:** 玩家在手機與寬螢幕都能以核准的 Variant A「招牌擂台」完成四次飲食抉擇、抽籤、辯護與結果；角色和整卡選擇維持主要層級，精簡夜市元素提供辨識度而不壓過任務，所有狀態也有 reduced-motion 與非色彩替代。

**Blocked by:** 06 — 以四次飲食抉擇完成備援流程.

**Status:** claimed

- [ ] 完整遊戲使用單一紅色主招牌、兩顆可見燈泡、深色油布／金屬面板及節制的琥珀回饋，呈現可辨識但不密集的台灣夜市氣氛。
- [ ] 不加入裝飾側招牌、棚架、懸掛燈串、攤販器具、凳子、廟宇屋頂、舞台燈、賭場／賽博龐克元素或背景生成文字。
- [ ] 紅／青只表示當前兩個選擇席位並可跨題重用；每個飲食立場仍由名稱與角色辨識，琥珀只標示目前步驟、已記錄選擇、抽中項目與主要行動。
- [ ] 手機與寬螢幕維持「遊戲標頭 → 進度 → 主要任務 → 次要情境／模型入口」的相同語意順序；手機垂直堆疊，寬螢幕將相同單元左右排列。
- [ ] 飲食立場卡整張可點，角色與立場名稱優先；已選狀態同時具備文字、勾選、邊框與照明，不只依賴紅／青或琥珀色。
- [ ] 選擇記錄、抽籤揭曉與結果轉場使用短促且不拖慢流程的原生回饋；手機可提供輕觸覺，但不加入音效。
- [ ] 系統要求減少動態效果時，所有移動、跳動或閃爍改以靜態標記與淡入式說明呈現，資訊與操作時序不改變。
- [ ] 結果頁讓抽中立場的大型角色、名稱、標記、固定質疑、裁決與主要行動維持主要層級，四項本局信仰清單作為可辨識的次要情境。
- [ ] 430 × 932 手機與 1280 × 900 寬螢幕無水平 overflow，兩者呈現同一遊戲而非不同資訊架構；Variant B 只可作寬版密度參考，Variant C 不採用。
- [ ] Widget 或視覺回歸驗證代表性選擇、鎖定、抽籤、辯護與結果狀態，且不依賴 prototype HTML/CSS/JavaScript 或直接搬用其程式碼。
