# 日誌系統安全性改進

**日期:** 2025-12-23
**版本:** 0.0.4-r2
**相關議題:** iOS 分享錯誤修復、Release Mode 日誌增強、資訊安全改進

---

## 問題背景

### 1. iOS 分享功能錯誤
```
PlatformException(error, sharePositionOrigin: argument must be set,
{{0, 0}, {0, 0}} must be non-zero and within coordinate space of source view)
```

在 iPad 上使用 `share_plus` 分享文件時,必須提供 `sharePositionOrigin` 參數來指定分享彈窗的位置。

### 2. Release Mode 診斷資訊不足
- Release Mode 下預設只記錄 `WARN` 和 `ERROR` 級別的日誌
- 用戶回報問題時,開發者無法獲得足夠的診斷資訊 (缺少 `DEBUG` 和 `INFO` 級別)
- UI 顯示所有日誌對一般用戶而言過於複雜

### 3. 資訊安全隱私風險
- 日誌可能包含敏感資訊 (API tokens, passwords)
- 診斷報告包含完整檔案路徑,可能洩露用戶名稱
- 用戶不清楚分享的內容包含什麼資訊
- 缺乏敏感資訊過濾機制

### 1. 修復 iOS 分享錯誤

**檔案:** `lib/ui/shared/widgets/log_export_dialog.dart`

#### 實作細節

在 `_shareLogs()` 和 `_shareAllLogs()` 方法中:


**重點:**
- 必須在任何 `await` 操作前獲取 `context.findRenderObject()`
- 避免跨異步間隔使用 `BuildContext`

#### UI 顯示過濾

**檔案:** `lib/ui/shared/widgets/log_export_dialog.dart`

```dart
Future<void> _loadLogs() async {
  final content = await CrashReportingService.instance.exportLogs(maxLines: 500);

  // 過濾日誌,只在 UI 顯示 WARNING 及以上等級的訊息
  final lines = content.split('\n');
  final filteredLines = lines.where((line) {
    // 檢查日誌等級標記 [W] 或 [E]
    return line.contains('[W]') || line.contains('[E]');
  }).toList();

  displayContent = filteredLines.isEmpty
      ? '無警告或錯誤訊息（完整日誌請使用分享功能查看）'
      : filteredLines.join('\n');
}
```

**設計理念:**
| 場景 | 日誌級別 | 目的 |
|------|---------|------|
| **UI 顯示** | `WARN` + `ERROR` | 只顯示重要問題給用戶 |
| **分享日誌** | `DEBUG` + `INFO` + `WARN` + `ERROR` | 提供完整資訊給開發者 |

### 3. 資訊安全改進

#### 3.1 敏感資訊自動過濾

**檔案:** `lib/utils/logger.dart`

實作 `_sanitizeMessage()` 方法,在寫入日誌前自動過濾:

```dart
static String _sanitizeMessage(String message) {
  var sanitized = message;

  // API tokens/keys (Bearer, token=, api_key=)
  sanitized = sanitized.replaceAllMapped(
    RegExp(r'(Bearer\s+|token[=:]\s*|api[_-]?key[=:]\s*)([A-Za-z0-9_\-\.]+)',
           caseSensitive: false),
    (match) => '${match[1]}[REDACTED]',
  );

  // Authorization headers
  sanitized = sanitized.replaceAllMapped(
    RegExp(r'(Authorization[=:]\s*)([^\s,]+)', caseSensitive: false),
    (match) => '${match[1]}[REDACTED]',
  );

  // 密碼
  sanitized = sanitized.replaceAllMapped(
    RegExp(r'(password[=:]\s*)([^\s,]+)', caseSensitive: false),
    (match) => '${match[1]}[REDACTED]',
  );

  return sanitized;
}
```

**保護範圍:**
- Bearer tokens
- API keys (api_key, apiKey, api-key)
- Authorization headers
- Passwords

**範例:**
```
❌ 原始: Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
✅ 過濾: Authorization: Bearer [REDACTED]

❌ 原始: api_key=sk_1234567890abcdef
✅ 過濾: api_key=[REDACTED]
```

#### 3.2 路徑匿名化

**檔案:** `lib/ui/shared/widgets/log_export_dialog.dart`

```dart
String _sanitizePath(String path) {
  // 移除用戶名稱,只保留相對路徑結構
  final parts = path.split('/');
  final userIndex = parts.indexOf('Users');
  if (userIndex >= 0 && userIndex + 1 < parts.length) {
    parts[userIndex + 1] = '[USER]';
  }
  return parts.join('/');
}
```

在診斷報告中應用:
```dart
storageInfo.forEach((key, value) {
  buffer.writeln('$key: ${_sanitizePath(value)}');
});
```

**範例:**
```
❌ 原始: /Users/linboshen/Documents/app.log
✅ 匿名: /Users/[USER]/Documents/app.log
```

## 技術細節

### BuildContext 跨異步使用問題

**錯誤示範:**
```dart
Future<void> _shareLogs() async {
  final confirmed = await _showShareConfirmation();  // await

  // ❌ 錯誤: context 可能已經失效
  final box = context.findRenderObject() as RenderBox?;
}
```

**正確做法:**
```dart
Future<void> _shareLogs() async {
  // ✅ 正確: 在任何 await 之前獲取
  final box = context.findRenderObject() as RenderBox?;
  final sharePositionOrigin = /* ... */;

  final confirmed = await _showShareConfirmation();
  // 使用之前保存的 sharePositionOrigin
}
```

### 正則表達式效能考量

敏感資訊過濾使用了多個正則表達式,但只在日誌寫入時執行一次:

```dart
void _log(Level lvl, Object? msg, {Object? error, StackTrace? st}) {
  // ...
  final sanitizedMsg = _sanitizeMessage(msg.toString());
  final sanitizedError = error != null ? _sanitizeMessage(error.toString()) : null;
  // 只在這裡過濾一次,寫入的就是乾淨的內容
}
```

不會影響執行效能,因為:
1. 只在實際記錄日誌時才執行
2. 日誌寫入本身就是 I/O 操作,正則處理的開銷相對很小
3. 使用 `replaceAllMapped` 一次遍歷完成所有替換

## 安全性評估

### 修改前風險等級: ⚠️⚠️⚠️

| 風險 | 嚴重程度 | 說明 |
|------|---------|------|
| 敏感資訊洩露 | 🔴 高 | 無任何過濾機制 |
| 隱私洩露 | 🟡 中 | 完整路徑包含用戶名稱 |
| 缺乏知情同意 | 🟡 中 | 用戶不知道分享什麼 |

### 修改後風險等級: ✅✅✅

| 風險 | 嚴重程度 | 防護措施 |
|------|---------|---------|
| 敏感資訊洩露 | 🟢 低 | Logger 層自動過濾 |
| 隱私洩露 | 🟢 低 | 路徑匿名化 |
| 缺乏知情同意 | 🟢 低 | 確認對話框 + 警告訊息 |

## 進一步改進建議

### 短期建議 (可選)

1. **分享後清理**
   ```dart
   // 分享完成後刪除臨時診斷報告
   try {
     await reportFile.delete();
   } catch (_) {}
   ```

2. **日誌保留期限**
   ```dart
   // LogFileService 中添加
   static const int maxLogAgeDays = 7;

   // 刪除超過 7 天的日誌
   for (var file in oldFiles) {
     final age = DateTime.now().difference(file.lastModifiedSync());
     if (age.inDays > maxLogAgeDays) {
       await file.delete();
     }
   }
   ```

### 長期建議 (未來版本)

1. **日誌加密**
   - 使用設備 keychain/keystore 加密日誌文件
   - 分享時提供解密金鑰

2. **更精細的過濾**
   - 電子郵件地址
   - 手機號碼
   - IP 地址
   - 信用卡號 (如果有)

3. **可配置的分享選項**
   - 允許用戶選擇分享哪些資訊
   - 預覽診斷報告內容

4. **匿名化 ID**
   - 生成臨時匿名 ID 取代用戶識別資訊
   - 開發者可通過 ID 關聯問題,但無法識別用戶

## 總結

這次改進同時解決了三個重要問題:

1. ✅ **功能修復**: iOS 分享錯誤
2. ✅ **可用性提升**: Release Mode 診斷資訊完整,但 UI 簡潔
3. ✅ **安全強化**: 多層次的敏感資訊保護機制

設計理念:
- **對用戶友善**: UI 只顯示重要訊息,有清楚的隱私提示
- **對開發者友善**: 分享時提供完整診斷資訊
- **對隱私友善**: 多重過濾機制,最小化風險

這是一個平衡了**可用性**、**安全性**和**隱私保護**的解決方案。
